# C 파트 AGENTS 규칙 (장소·지도·AI 추천·교통)

공통 `AGENTS.md`를 먼저 따른다. 이 파일과 부딪히면 공통 규칙이 우선이다.
세부 동작은 세부기능정의서 v33의 해당 기능 ID 행을 그대로 따른다.

## 1. 담당 범위

### 기능 (23개)
- 장소·지도: PLC-01-01 키워드 검색·자동완성, PLC-01-02 장소 정보 표준화, PLC-01-03 즐겨찾기·후보 추가 연결, PLC-02-01 장소 상세·권장 체류시간, PLC-03-01 공통 지도 컴포넌트, PLC-03-02 방문 순서 핀·목록 연동, PLC-03-03 경로선·지도 범위 맞춤
- AI 추천: AIT-01-01 조건 설정·검증, AIT-01-02 요청 데이터 구성·개인정보 제외, AIT-02-01 날짜 배분·방문 순서, AIT-02-02 시간표 생성·제약 검사, AIT-04-01 항목별 다시 추천, AIT-05-01 미리보기·비교, AIT-06-01 적용·재검증, AIT-07-01 생성 상태·중복 방지·재시도
- 교통·경로: RTE-01-01 기본 이동수단, RTE-02-01 구간 경로·이동시간 조회·보관, RTE-02-02 구간 이동 정보 표시, RTE-03-01 구간 교통비, RTE-03-02 교통비 경비 반영, RTE-04-01 여행별 출발 설정, RTE-04-02 개인 안내 표시·노출 차단, RTE-05-01 외부 길찾기 연결

### 폴더
- 백엔드: `com.planmate.place`, `com.planmate.ai`, `com.planmate.route`
- 프론트: `features/place`, `features/ai`, `features/route`

### 테이블
- 권장 체류시간 기준(RECOMMENDED_STAY), 외부 호출 기록(API_CALL_LOG), 구간 경로(ROUTE_SEGMENT), 개인 출발(PERSONAL_TRANSFER)
- 교통비 반영 연결(FARE_EXPENSE_LINK): C가 주인(route/), D는 FareService로 사용
- AI는 테이블이 없다. 조건은 저장하지 않고, 추천안은 화면이 들고 있다.
- 도시(CITY)·여행 기본 이동수단(TRIP.TRAVEL_MODE)은 B의 테이블이라 B의 서비스로 읽고 바꾼다.

## 2. 장소 규칙

- 장소 식별값 = 제공자 + 장소 ID. 국내 여행은 카카오, 해외 여행은 구글(도시의 MAP_PROVIDER). 한 여행 안에서 섞지 않는다.
- 공통 장소 형식(B·D·A에 넘기는 모양): 제공자(KAKAO / GOOGLE / ADDRESS)·장소 ID·장소명·주소·위도·경도·카테고리·조회 시각. 필드 이름은 contracts에 적고 팀과 맞춘다. ADDRESS(장소 ID 없는 주소)는 후보·일정에 넣을 수 없고 개인 출발 장소에만 쓴다.
- 카테고리 코드: ATTRACTION / FOOD / CAFE / SHOPPING / LODGING / TRANSPORT / ETC (관광명소 / 식당 / 카페 / 쇼핑 / 숙소 / 교통(공항·역) / 기타)
- 권장 체류시간(RECOMMENDED_STAY): 관광명소 180분 / 식당 90분 / 카페 60분 / 쇼핑 90분 / 기타 60분. 숙소·교통처럼 값이 없으면 B가 30분을 쓴다.
- 검색: 앞뒤 공백 제거 후 1~50자, 자동완성 후보 5개, 결과 10개씩(끝까지 내리면 다음 10개), 여행 도시 중심 반경 20km 우선, 해외는 한국어로 요청(없으면 현지어). 도시 중심에서 100km 넘으면 경고(저장은 허용). '결과 없음'과 '조회 실패'를 구분한다.
- 좌표: (lat, lng) 숫자, 소수 7자리(NUMBER(10,7) -> BigDecimal). (0, 0)이나 빈 값은 '위치 미확인'.
- 장소 상세: 저장하지 않고 조회만. 제공자가 준 정보만 보여 주고 없으면 '정보 없음'(추정 금지). 구글 상세는 이름·주소·좌표·영업시간·전화·웹사이트만 요청(사진 제외). 구글 자동완성은 세션 토큰으로 자동완성 여러 번 + 상세 1번을 묶는다.
- 저장 범위: 구글 장소는 장소 ID만 오래 저장하고 나머지는 이용 조건 기간 안에서만 보관한다.
- 장소·경로 API는 서버를 거쳐 호출한다(REST 키를 화면에 노출하지 않음). 지도 JavaScript 키는 허용 도메인만(카카오 도메인 등록, 구글 리퍼러 제한).
- 외부 호출마다 API_CALL_LOG에 종류(PLACE_SEARCH / AUTOCOMPLETE / AI / PLACE / ROUTE)·결과·응답 시간을 남긴다. 검색어 원문은 남기지 않는다.
- 검색 결과 버튼(PLC-01-03): 하트(빈 하트 = 보관함에 없음, 채운 하트 = 저장됨) + [후보에 추가](빈 체크 / "후보에 있음" 채운 체크). C는 직접 저장하지 않고 공통 장소 형식을 A(보관함)·B(후보)에 넘긴다.
- 입장료는 개발 후순위(여건이 되면).

## 3. 지도 규칙 (MapView.tsx)

- 국내 카카오맵·해외 구글맵을 하나의 컴포넌트로 감싼다. B의 일정 화면, D의 공개 상세, 장소 검색 화면이 같은 방식으로 쓴다.
- 속성: provider·mode(EDIT / VIEW)·center·zoom·pins·segments·selectedDay·highlightedId·onPinClick. 이름을 바꾸려면 B·D와 먼저 맞춘다.
- 범위 맞춤: 핀 2개 이상이면 전체 보기(여백 40px), 1개면 확대 수준 15, 0개면 도시 중심. 같은 날짜 안에서 사용자가 지도를 움직인 뒤에는 자동 맞춤 안 함(날짜를 바꾸면 다시 맞춤).
- 핀: 방문 순서 번호, 일차별 색은 무지개 7색(빨강·주황·노랑·초록·파랑·남색·보라) 차례로. 같은 장소 여러 번 방문은 핀 하나에 번호 함께(예: 2·5). 핀 표시만으로는 아무것도 저장하지 않는다.
- 검색 결과 핀: 보관함 장소 하트 / 후보 체크 / 필수 후보 별 / 둘 다면 후보 표시 / 아니면 빈 원. 후보 탭의 후보 핀: 체크(필수는 별).
- 경로선: 실제로 조회한 구간만 실선. 미확인·조회 중 구간은 회색 점선 + 라벨. 좌표가 많으면 모양이 크게 안 바뀌는 범위에서 줄여 그린다.
- D의 공개 화면(VIEW 모드)은 경로선 대신 장소끼리 직선으로 잇는다(경로 API 호출 없음).

## 4. AI 추천 규칙

- 대상: 여행의 공동 후보 전체(필수 방문 포함). 개인 보관함은 대상 아님.
- 조건(저장하지 않음): 일정 밀도 여유(하루 3곳) / 보통(4~5곳) / 알참(6곳 이상), 활동시간 기본 09:00~22:00, 첫날 도착 후 준비 30분, 마지막 날 출발 여유 해외 공항 120분·역/터미널 30분.
- 계산 순서: 서버가 직선거리로 날짜 배분 -> 그날 장소끼리 실제 이동시간 조회(10곳 이하면 모든 쌍, 넘으면 각 장소에서 가까운 5곳까지, 필수·출발·도착이 들어간 쌍은 항상) -> AI(LLM)가 하루 방문 순서와 추천 이유 -> 서버가 총 이동시간 재계산·서버 기준 순서와 비교. 날짜 배분·이동시간 계산·조건 검사는 서버가 하고 LLM에게 맡기지 않는다.
- 요청당 추천안 1개. 배치 못 한 장소는 공동 후보로 남기고 장소명 목록만 보여 준다(이유는 적지 않음).
- AI에 보내는 정보는 허용 목록만: 도시, N일차, 활동시간·밀도, 도착·출발·숙소 장소, 후보(식별값·이름·카테고리·좌표·영업시간·권장 체류시간·필수 여부), 고정 일정(일차·시간), 구간 이동시간. 허용 목록 밖 필드가 있으면 호출하지 않고 오류 기록.
- 보내지 않는 정보: 집<->공항 정보, 계정·인증, 메모, 1:1 문의·답변, 초대 링크, 참여자 이름·이메일, 경비, 실제 날짜.
- AI 호출 기록은 여행 ID·요청 식별값·사용량·응답 시간만. 요청 원문은 저장하지 않는다.
- 상태: 생성 중 / 성공 / 검토 필요 / 실패(화면에만 표시). 실패 원인: AI 서비스 오류 / 시간 초과 / 호출 한도 초과 / 경로 조회 실패 / 응답 형식 오류 / 알 수 없는 오류(원인을 지어내지 않음). 자동 재시도는 응답 형식 오류만 1번.
- 재요청 간격: 같은 회원은 마지막 요청 후 1분(어느 여행이든 회원 기준, 서버 메모리). 실패한 요청은 간격 계산에 넣지 않는다. 화면에서 막아도 서버에서 다시 검사. 안내: "1분에 한 번만 추천받을 수 있어요. n초 뒤에 다시 시도해 주세요."
- 생성 중 창을 닫아도 서버 처리는 계속하고, 다시 열면 상태를 이어서 보여 준다.
- 미리보기: 고정 항목만 '고정'으로 표시, 일정에서 빠진 항목은 목록에 안 보임. [비교하기]는 새 페이지에서 왼쪽 원래 일정, 오른쪽 추천 일정.
- 항목별 다시 추천: 순서·방문시간은 그대로 두고 장소만 일정에 없는 다른 공동 후보로 바꾼다. 고정 항목은 불가.
- 적용(AIT-06-01): 첫 버전은 전체 적용만. 적용 직전 권한·조건·최신 상태 재검사. 막는 조건: 생성 뒤 대상 범위 방문 항목·고정 상태 변경(VISIT.VERSION 비교, 메모만 바뀐 건 제외), 여행 기간 변경, 필수 방문 누락, 고정 충돌, 이동시간 미확인. 미리보기 중 다른 참여자가 바꾸면 "다른 참여자가 일정을 바꿨어요. 이 추천은 바뀌기 전 일정으로 만들었어요."
- 저장은 반드시 B의 ScheduleSaveService를 부른다. 별도 저장 경로를 만들지 않는다. 같은 추천안·같은 요청 식별값은 한 번만 적용. 추천에서 빠진 기존 방문은 일정에서 빼고 장소는 공동 후보에 남긴다(메모는 방문과 함께 삭제).
- AI 서비스 호출은 `ai/client/AiClient`에서만. 키는 환경 변수.

## 5. 교통·경로 규칙

- 기본 이동수단(TRIP.TRAVEL_MODE): 여행당 1개, TRANSIT_WALK(기본값) / CAR. 바꾸면 모든 구간 다시 조회. 보기는 참여자, 변경은 소유자·편집 참여자. 변경 저장·전파는 B의 서비스로.
- 직선 700m 이하 구간은 도보 경로로 조회(ROUTE_SEGMENT.TRAVEL_MODE = WALK).
- 경로 제공자: 국내 대중교통·도보는 카카오맵, 자동차는 카카오모빌리티, 해외는 구글 Routes. 국내 대중교통 이동시간은 출발 시각 미반영이라 '예상' 표시. 카카오 대중교통 응답에 처음·마지막 도보 상세가 없으면 지도에 도보 선을 그릴 때만 도보 경로 API를 더 부른다.
- 조회 시점: B가 일정 저장에 성공한 뒤 넘겨준 새 구간만. [다시 조회]는 소유자·편집 참여자.
- 캐시(ROUTE_SEGMENT): 출발 + 도착 + 이동수단(해외 대중교통은 + 출발 시간대 1시간 단위)으로 24시간(EXPIRES_AT). 동시 외부 호출은 5개까지.
- 미확인 이동시간·요금을 0분·0원으로 바꾸지 않는다. 도보 0원은 실제 무료로 구분한다.
- 공통 구간 형식: 출발·도착 장소 식별값, 이동수단, 이동시간(분), 거리(m), 경로 좌표, 대중교통 안내, 요금, 상태, 출처, 조회 시각, 출발 시각 반영 여부. 공개 화면(D)에는 요금을 빼고 준다.
- 출처 표시: 시간표 목록 맨 아래 "경로 정보: Google"처럼 제공자만.
- 교통비(RTE-03-01): 대중교통은 항상 성인 1인·교통카드 금액(현금 요금만 있으면 '요금 미확인'), 통행료·택시는 전체 금액. 요금이 없으면 '미확인'. 일차 합계는 같은 통화끼리, 섞이면 통화별로.
- 경비 반영(RTE-03-02): 사용자가 확인한 금액만 D의 경비로 넘긴다(확인 전 총액 변화 없음). 일차별 합계·구간별 둘 다 제공하고 미리보기에서 고름, 같은 일차를 두 방식으로 반영 금지. 대중교통은 1인 금액·통행료는 전체 금액이라는 구분만 넘기고 인원은 곱하지 않는다(D가 곱함). 미확인 구간은 반영하지 않고 "미확인 n건은 직접 입력해 주세요". 이미 반영된 일차·구간이면 갱신할지 묻는다(FARE_EXPENSE_LINK, 경비 항목 하나에 연결 하나). 구간이 사라져도 반영 항목을 자동 삭제하지 않고 "연결 구간이 바뀌었어요".
- 개인 출발(RTE-04): A의 집 주소를 출발 장소 처음 값으로 채운다(불러오기 버튼 없음). 출발 공항은 국내 15곳(가나다순: 광주·군산·김포·김해·대구·무안·사천·양양·여수·울산·원주·인천·제주·청주·포항경주)에서 고르고 PERSONAL_TRANSFER에 여행·회원당 1행. 출발 장소는 저장하지 않는다. 본인만 볼 수 있고 공동 일정·공개·복제·PNG·AI·로그·관리자 화면 어디에도 나가지 않는다.
- 외부 길찾기(RTE-05-01): 국내 여행은 카카오맵, 해외 여행은 구글 지도 길찾기 화면을 링크로 연다(키 필요 없음). 사이트 안에서 공항 경로 계산·출발 시각 역산은 하지 않는다.

## 6. 다른 파트와 주고받는 것

### C가 제공

## 7. 문서끼리 다른 곳 (코드 쓰기 전에 사람에게 확인)

- 추천에서 빠진 기존 방문의 메모: 기준값 '추천에서 빠진 기존 방문'은 "메모는 후보 장소에 보관", AIT-06-01과 B 기준값(11/23)은 "방문 항목과 함께 삭제". 이 파일은 삭제로 적었다.
- 검색 결과의 [일정에 추가]: 기준값 '검색 결과 버튼'에는 하트와 [후보에 추가]만 있고 "[+](일정에 추가)는 없음", PLC-01-03·PLC-05-01·SCH-02-01에는 후보 탭 검색 결과에서 일정에 바로 추가하는 동작이 있다.
- 권장 체류시간 설명의 "사용자가 일정 추가 창에서 바꿀 수 있음"과 B의 "장소 추가 창 없음(시간은 자동, 바꾸려면 일정 카드 [수정])".
- 어떤 AI 서비스(API)를 쓸지는 기능정의서에 없다. 정해지면 이 파일과 `.env.example`에 적는다.
