# D 파트 AGENTS 규칙 (공개 커뮤니티·예상 경비)

공통 `AGENTS.md`를 먼저 따른다. 이 파일과 부딪히면 공통 규칙이 우선이다.
세부 동작은 세부기능정의서 v33의 해당 기능 ID 행을 그대로 따른다.

## 1. 담당 범위

## 2. 커뮤니티 규칙

- 이용 제한 회원: 커뮤니티는 보기만(목록·상세·댓글 목록·내 북마크 목록·공개 상태 보기). 공유·게시·제목 수정·비공개 전환·좋아요·북마크·복제·댓글·신고는 막는다(A의 AccountStatusChecker). 커뮤니티 밖 기능은 모두 가능.
- 공유 흐름: 여행 화면 [공유하기] -> 공개용 제목·소개·사진 -> [다음] -> 미리보기 -> [게시]. 여행을 만들 때는 공개 여부를 고르지 않는다. 소유자만.
- 게시물: 여행당 1개(UQ_PUBLIC_POST_01). 공개 중이면 공유하기 비활성. 비공개로 바꾼 뒤 다시 공유하면 같은 게시물을 되살린다(좋아요·댓글 유지). 시간표에 방문 일정이 없으면 공유 불가("일정을 추가한 뒤 공유할 수 있어요."). 게시 확인 문구 "다른 회원이 이 일정을 보고 복제할 수 있어요. 게시할까요?". 같은 요청 두 번 처리 방지(DuplicateRequestChecker).
- 공개용 제목 1~40자(미리 채우지 않음), 소개 0~100자(줄바꿈은 소개만), 사진은 선택·최대 1장(PUBLIC_POST.POST_IMAGE_URL, 없으면 기본 배경). 사진 파일 형식·크기는 아직 미정.
- 공개 일정은 따로 복사하지 않는다. 원래 여행의 현재 일정에서 공개 허용 항목만 서버가 골라 응답한다.
  - 공개: N일차별 장소·순서·방문시간·체류시간·이동수단·이동시간·거리·대중교통 안내(노선·환승·도보 구간), 숙소 포함
  - 제외: 실제 날짜, 경비, 참여자, 메모, 집<->공항, 고정 상태, 구간 요금, 날씨
- 게시물 갱신 기능은 없다. 제목·소개·사진만 고친다(PUB-02-05, UPDATED_AT 갱신, "수정 10.28" 표시). 일정·구간은 원래 여행을 따라간다.
- 비공개 전환: IS_PUBLIC = 'N'. 관리자 비공개(ADMIN_HIDDEN = 'Y')는 소유자가 공개로 못 바꾼다. 관리자가 비공개로 바꾸면 소유자에게 알림 "관리자에 의해 비공개 처리되었습니다."(A의 NotificationService).
- 원래 여행이 휴지통에 가면 노출 중단, 복원되면 삭제 직전 공개 상태로(B가 부름).
- 공개 상태 표시: 내 여행 목록 카드·내 게시글에 '공개' / '비공개' 글자(색 구분 없음). 버튼 이름 [비공개 전환], [공개 전환](소유자가 비공개로 바꾼 게시물만).
- 목록(비회원 가능): 10개씩 무한 스크롤(마지막 게시물 기준으로 이어 받기). 최신순 = 처음 게시 시각(PUBLISHED_AT, 제목을 고쳐도 순서 그대로), 좋아요순 = LIKE_COUNT, 같으면 최신 게시순. 검색어 0~50자 부분 일치, 도시는 등록된 모든 도시(처음 "전체 도시"), 일수 1~7일("3일"로 표시).
- 상세(비회원 가능): N일차별 일정, 지도는 C의 MapView VIEW 모드로 장소끼리 직선 연결(경로 API 호출 없음). 내 게시물이면 좋아요·[제목·소개 수정]·[비공개 전환]만 보이고 신고·북마크·복제는 없다. 로그인이 필요하면 로그인 후 원래 게시물로 돌아오고, 누르려던 동작은 다시 눌러야 한다.
- 좋아요: 회원당 게시물 하나에 1번(UQ_POST_LIKE_01), LIKE_COUNT 함께 갱신. 글자 버튼 "좋아요 12".
- 북마크: 회원당 200개, 담은 시각 최신순. 좋아요·보관함·복제와 다른 동작.
- 복제(PUB-07): 정상 회원. 새 여행의 시작일·인원을 받아 B의 여행 생성(TRP-01-03, 3개 제한 포함)으로 새 비공개 여행을 만들고, B의 공동 후보 추가와 일정 저장(ScheduleSaveService)으로 일정을 넣고, C에 구간 조회를 맡긴다.
  - 복사: 장소·순서·방문시간·체류시간·기본 이동수단(장소는 공동 후보로도 추가). 제목은 공개용 제목.
  - 복사 안 함: 날짜·경비·메모·참여자·좋아요·댓글·고정·필수 표시·체크리스트·AI 조건.
  - 복제 원본 게시물 ID는 저장하지 않는다(11/23 결정). 재확인 안내는 복제 직후 한 번만(저장 안 함).
- 댓글: 1~500자, 줄바꿈 허용, 대댓글·멘션 없음. 같은 회원 10초에 1개. 오래된 순 20개씩. 수정하면 IS_EDITED = 'Y'("수정됨"). 새 댓글이면 게시물 작성자에게 알림(본인 댓글 제외, 알림에는 댓글 ID만 넘기고 미리보기 30자는 A가 보여 줄 때 원문에서 읽음).
- 신고: 사유 SPAM / ABUSE / PRIVACY / NICKNAME / ETC(기타는 1~300자). 처리 전 같은 대상 중복 신고 불가, 기각된 뒤에는 다시 가능. 자동 숨김 없음(관리자 판단). POST_ID와 COMMENT_ID를 둘 다 채우지 않는다(CK_REPORT_01). 신고된 댓글은 숨김 없이 관리자가 바로 삭제한다.

## 3. 경비 규칙

- 구분: 공통(SCOPE = COMMON) / 개인(PERSONAL). 분류: TRANSPORT / LODGING / FOOD / SIGHTSEEING / ETC(교통 / 숙박 / 식비 / 관광 / 기타).
- 계산 방식은 공통 경비만: TOTAL(전체 금액) / PER_PERSON(1인당 x 여행 인원). 개인 경비는 금액만(CALC_TYPE 비움, CK_BUDGET_ITEM_02). 개인 경비는 만든 사람을 꼭 채움(CK_BUDGET_ITEM_01).
- 항목명 1~50자, 메모 0~200자(공통 경비만, 펼친 칸에서 작성). 금액은 하나만 입력, 0 이상 최대 1억(원 기준), 통화 표준 자릿수(엔·원 0자리, 달러·유로 2자리). 통화 기본값은 여행 도시 통화. 공통 경비 여행당 200개, 개인 경비 회원마다 200개. 분류 안 정렬은 추가한 순서.
- 권한: 보기는 모든 참여자(개인 경비도 모두 볼 수 있음). 공통 편집은 소유자·편집 참여자, 개인 편집은 주인 본인. 조회 참여자는 공통·개인 모두 입력 불가.
- 동시 수정: 공통·개인 모두 나중에 저장한 값으로 덮어쓴다(VERSION 칸 없음). 변경 전파는 B의 SyncService.
- 예산 기준 계산(BUD-02-01): 곱할 값(여행 인원·일수 1~7·횟수 1~99)으로 계산한 결과를 공통 경비(TOTAL)로 넣는다(AMOUNT_SOURCE = BUDGET_RULE, 기준은 ESTIMATE_BASIS).
- 교통비 반영(BUD-02-02): C의 반영 미리보기(RTE-03-02)에서만 들어온다(D의 반영 대기 목록 없음). 대중교통 운임은 1인 금액 x 여행 인원, 자동차 통행료는 전체 금액(AMOUNT_SOURCE = ROUTE_FARE). 연결 기록(FARE_EXPENSE_LINK)은 C가 쓴다.
- 합계: 금액이 있는 항목을 계산 방식별로 계산해 통화별로 더하고 원화 합산을 항상 함께 보여 준다([전체 합계 보기] 버튼 없음). 공통 경비 합계는 [전체] 탭 맨 오른쪽 아래, 경비 탭 맨 위는 내 1인 경비만.
- 내 1인 경비 = 공통 경비 합계 / 여행 인원 + 내 개인 경비 합계. 통화별로 계산하고 통화 표준 자릿수로 마지막에 한 번 반올림.
- 부분 합계: 계산에서 빠진 항목이 있으면 부분 합계임을 알리고 빠진 항목과 사유(가격 미확인 / 환율 없음)를 보여 준다. 항목별 원화 환산·적용 환율은 표시하지 않는다.
- 여행 인원이 바뀌면 B가 알려 주고 D가 다시 계산한다.

## 4. 환율 규칙

- 한국수출입은행 환율 API, 서버를 거쳐 호출(키는 환경 변수). `budget/job/ExchangeRateScheduler`가 매일 오전 11시 이후 1번 조회(`@Scheduled`의 zone = "Asia/Seoul"). 모든 여행이 같은 오늘 환율을 쓴다(여행별 저장·[환율 갱신] 버튼 없음).
- EXCHANGE_RATE는 통화 + 발표 날짜(BASE_DATE)당 1행, UNIT은 1 또는 100(100단위로 발표되는 통화). 받은 값이 비면 이전 영업일 환율을 쓴다.
- 환율 위젯: 경비 탭에만, 국내 여행은 표시 안 함. "[100] 엔 = [910] 원" 형식으로 어느 칸에 넣어도 반대 칸 계산(저장 안 함) + 발표 날짜 + "환율은 오전 11시 기준으로 변경됩니다."

## 5. 다른 파트와 주고받는 것

### D가 제공
- A: ReportService(신고 목록·상세·처리 상태), 관리자 비공개·해제·댓글 삭제 API, 탈퇴 때 본인 공개 게시물 비공개·댓글·좋아요·북마크 처리, 나가기·내보내기·탈퇴 때 개인 경비 삭제(여행 + 회원 기준), 소유권 이전 때 게시물 작성자(AUTHOR_ID) 변경
- B: 여행 카드의 공개 상태, 메인 화면 인기 공개 여행 3개, 원래 여행 삭제·복원 때 게시물 노출 중단·재개, 인원 변경 때 경비 재계산
- C: 경비 항목 만들기·갱신(교통비 반영)

### D가 부름
- A: AccountStatusChecker·TripAccessChecker·AdminAccessChecker, NotificationService(새 댓글·관리자 비공개), 닉네임 조회(MemberService)
- B: TripService(여행 생성·상태·인원·도시), 공동 후보 추가, ScheduleSaveService(복제), 저장된 시간표 조회(공개 미리보기·상세), SyncService(경비 전파)
- C: MapView VIEW 모드, 공개용 구간 정보(요금 제외), 새 여행 구간 조회(복제), FareService

## 6. 문서끼리 다른 곳 (코드 쓰기 전에 사람에게 확인)

- 복제 원본 기록: 기준값 '복제 원본 기록'(11/05)은 "새 여행에 복제 원본 게시물 ID 저장", PUB-07-02·03(11/23)과 DB설계서 v7은 칸이 없다. 이 파일은 저장하지 않는 것으로 적었다.
- 사진 파일 형식·크기와 저장 위치는 아직 정하지 않았다.
